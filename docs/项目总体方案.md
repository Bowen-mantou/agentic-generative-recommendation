# Agentic Generative Recommendation
## 基于用户记忆与结构化判断的智能体生成式推荐系统

**项目类型：** Generative Recommendation / Agentic Recommendation

**项目定位：** 构建一个融合生成式推荐、用户记忆、混合召回、结构化判断与自适应决策的智能体推荐系统。

**文档版本：** V1.1（统一技术路线修订版）

---

# 一、项目背景与研究动机

传统推荐系统主要依赖用户历史交互行为，通过协同过滤、序列建模或向量检索等方式预测用户可能感兴趣的商品。

随着大语言模型的发展，生成式推荐为推荐系统提供了新的实现思路：系统不仅可以根据用户历史行为生成推荐，还能够理解用户当前的自然语言需求，结合长期偏好和近期兴趣，动态调整推荐策略。

但单纯使用 LLM 生成推荐存在一些问题：

1. 用户长期偏好与短期兴趣难以持续维护。
2. 单一召回方式可能无法兼顾行为偏好和商品语义。
3. 生成模型可能推荐不满足用户硬性约束的商品。
4. 推荐系统缺少对推荐结果的独立验证机制。
5. 传统推荐流程通常采用固定策略，缺少根据推荐质量动态调整流程的能力。

因此，本项目计划构建一个 Agentic Generative Recommendation 系统，将生成式推荐模型、用户记忆、混合商品召回、结构化判断模型和自适应控制机制结合起来。

核心目标是：

**让推荐系统不仅能够生成推荐，还能够理解用户、检索商品、验证推荐结果，并根据当前推荐质量动态调整推荐策略。**

# 二、核心研究目标

本项目围绕五个核心方向展开。

### 1. 基于 Memory 的用户建模

使用 User Memory 替代独立的用户兴趣建模模型。

通过用户历史交互、近期行为和反馈构建持续更新的用户记忆，使系统能够同时理解用户的长期偏好、短期兴趣和具体历史事件。

### 2. 生成式商品推荐

引入 TIGER 生成式推荐模型，通过 Semantic ID 表示商品，并根据用户历史行为生成候选商品。

探索生成式推荐在商品召回、个性化推荐和长尾商品发现方面的能力。

### 3. 混合商品召回

结合 TIGER 生成式召回和 E5 + FAISS 向量召回。

利用两种召回方式的互补性扩大候选商品覆盖范围，再通过 Cross-Encoder Reranker 对候选商品进行精排。

### 4. 结构化商品判断

使用 DeepSeek API 作为 Judgment Model，通过独立 Prompt 和结构化输出协议，对候选商品与用户需求之间的匹配关系进行判断，重点关注用户偏好匹配、商品属性证据和判断不确定性。硬性约束由 Python Constraint Evaluator 执行，不由 Judgment 重复计算。

### 5. 自适应推荐决策

基于 Judgment 结果设计 Adaptive Controller。

系统不再完全采用固定的推荐流程，而是根据当前候选商品质量、约束满足情况和推荐多样性，动态决定是否继续召回、重新规划、调整候选商品或输出最终推荐。

# 三、整体系统架构

系统采用模块化、多 Agent 协作架构，以 LangGraph 作为统一的工作流编排框架。

整体流程如下：

```text
用户当前需求 + Mem0 User Context
              |
              v
    Recommendation Planner
          DeepSeek API
              |
       +------+----------------+
       |                       |
       v                       v
TIGER Retrieval             E5 + FAISS
       ^                       ^
       |                       |
SQLite InteractionHistory   Planner E5 Queries
       |                       |
       +-----------+-----------+
                   v
            Candidate Fusion
         E5 内部 RRF → 跨路 RRF
                   |
                   v
       Python Hard Constraint Evaluator
                   |
                   v
         Qwen3-Reranker-0.6B
                   |
                   v
            Judgment Model
              DeepSeek API
                   |
                   v
          Adaptive Controller
            LangGraph + Python
              |          |
           REPLAN       STOP
              |          |
           Planner    Recommendation
                        Generator
                      DeepSeek API
                           |
                           v
                    Top-K 商品推荐
                     + 推荐理由
                           |
                           v
                       用户反馈
                           |
                 +---------+---------+
                 |                   |
              Mem0 更新        SQLite Event Store
```

整个系统采用循环式推荐工作流，支持根据中间结果重新规划和执行，而不是简单的一次性推荐。

# 四、核心技术选型

| 系统模块 | 技术选型 | 主要职责 |
|---|---|---|
| Agent Orchestration | LangGraph | 多 Agent 工作流编排、状态管理、循环控制 |
| User Memory | Mem0 OSS + Qdrant + SQLite | 语义记忆管理、向量检索、原始证据与行为事件存储 |
| Planner | DeepSeek API | 用户需求理解、推荐计划生成 |
| Replanner | DeepSeek API | 根据推荐结果调整推荐策略 |
| Generative Retrieval | TIGER | Semantic ID 生成式商品召回 |
| Vector Retrieval | E5 + FAISS | 基于语义向量的商品召回 |
| Candidate Reranker | Qwen3-Reranker-0.6B | 商品候选精排；BGE-Reranker-v2-m3 作为对照基线 |
| Judgment Model | DeepSeek API | 商品级语义匹配与结构化判断 |
| Constraint Checker | Python Rules | 硬性约束检查 |
| Adaptive Controller | Python + LangGraph | 推荐流程控制与动作决策 |
| Recommendation Generator | DeepSeek API | 最终商品推荐与理由生成 |
| Trace Storage | JSONL + SQLite | 运行轨迹和实验数据保存 |

本项目不接入 JEV API。第一阶段的 Judgment 使用 DeepSeek API，不部署本地 Qwen Judgment 模型；后续可将判断轨迹整理为专用开源 Judgment 模型的训练数据。

同时，Cross-Encoder Reranker 与 Judgment Model 保持职责独立：前者负责候选商品相关性排序，后者负责更高层次的推荐合理性判断。

## 4.1 跨模块统一约定

为避免模块之间出现数据不兼容，统一以下基础约定：

1. **商品主键：** 内部统一使用 `product_id`。Amazon Reviews 2023 原始字段 `parent_asin` 保留在数据接入层，并映射到内部 `product_id`；TIGER 的 Semantic ID 仅用于生成和解码，不作为跨模块商品主键。
2. **语义记忆与行为序列分离：** Mem0 管理长期偏好、近期兴趣和事件摘要；TIGER 使用独立的、带时间戳的 `InteractionHistory` 行为事件序列。原始事件和来源证据保存在 SQLite，不从 Mem0 自由文本中拼接 TIGER 序列。
3. **Planner 计划协议：** Initial Planner 和 Replanner 共用模块二定义的 `RecommendationPlan`，包括 `intent`、`constraints`、`preferences`、`retrieval`、`ranking`、`clarification`、`assumptions` 和 `change_summary`。
4. **硬约束唯一执行：** 价格、品类等可确定性验证的硬约束由 Python Constraint Evaluator 统一执行；Judgment 不重复计算，Controller 读取校验结果。
5. **判断与排序分离：** Qwen3-Reranker-0.6B 负责相关性排序；DeepSeek Judgment 负责逐商品语义判断；Controller 负责 REPLAN / STOP。
6. **预算归 Controller 管理：** Planner 只能在允许枚举中选择召回预算档位；全局剩余调用次数、重规划轮数和 API 预算由 Controller State 管理。

# 五、整体工程设计原则

本项目采用模块化、可替换的工程架构。

主要遵循以下原则：

1. **统一工作流编排：** 使用 LangGraph 管理整个推荐流程，不自行从零开发 Agent 调度框架。
2. **模块解耦：** Planner、Memory、Retrieval、Judgment、Controller 和 Generator 均采用独立接口。
3. **状态统一管理：** 通过共享 State 维护用户记忆、推荐计划、候选商品、判断结果和当前执行状态。
4. **可恢复执行：** 利用 Checkpoint 保存工作流状态，支持异常处理和中断恢复。
5. **完整轨迹记录：** 保存每一轮 Agent 的输入输出、候选商品、模型判断和 Controller 动作。
6. **模型可替换：** Planner、Judgment 和 Generator 第一阶段通过独立 API Client 与 Schema 接入；Reranker、TIGER、E5 使用独立模型适配层，为后续模型替换和专项训练提供基础。

# 六、项目实施范围

本项目分为两个阶段。第一阶段以完整可运行链路和基础评测为交付目标；TIGER 按模块三约定先完成阶段 B 的最小真实生成式链路，阶段 A 的完整优化作为后续扩展。

### 第一阶段：完整系统搭建

使用 DeepSeek API、成熟开源组件和预训练模型，优先完成完整推荐工作链路。第一阶段不部署本地 Qwen Judgment 模型。

主要任务：

- 建立 User Memory 系统。
- 接入 DeepSeek Planner 和 Replanner。
- 完成 TIGER 阶段 B：构建可运行的 Semantic ID、用户历史序列、自回归生成和 Semantic ID 解码链路。
- 建立 E5 + FAISS 向量召回。
- 完成候选融合与 Reranker 精排。
- 接入 DeepSeek Judgment API，逐商品输出结构化判断。
- 使用 LangGraph 实现 Adaptive Controller。
- 接入 Recommendation Generator。
- 建立统一 Trace 和日志系统。

这一阶段不进行各个 Agent 的 SFT、LoRA 或其他专项训练。

优先保证所有模块能够协同运行，形成完整的端到端生成式推荐系统。

### 第二阶段：系统实验与性能分析

在课程设计基础链路完成后，可根据剩余资源开展 TIGER 阶段 A 的完整训练优化；阶段 A 不作为第一阶段端到端系统验收的前置条件。

在完整系统基础上开展实验，研究各个模块对推荐效果的贡献。

主要包括：

- User Memory 对个性化推荐的影响。
- TIGER 与 E5 混合召回的互补性。
- Reranker 对候选商品质量的改善。
- Judgment 对商品匹配和约束满足的改善。
- Adaptive Controller 对推荐质量、效率和多样性的影响。

本阶段重点完成模块消融、对照实验和错误案例分析。

# 七、实验评测体系

从推荐效果、用户个性化、推荐可靠性和系统效率四个方面进行评测。

| 评测维度 | 主要指标 |
|---|---|
| 推荐准确性 | Recall@K、NDCG@K、MRR |
| 召回效果 | Recall@50、Recall@100 |
| 推荐多样性 | ILD、Catalog Coverage |
| 个性化能力 | 用户偏好匹配率 |
| 推荐可靠性 | Constraint Violation Rate、Evidence Support Rate |
| Judgment 能力 | Accuracy、Macro-F1 |
| 系统效率 | Latency、API Cost、Token Usage |

重点通过对照实验和消融实验，验证各个核心模块是否真正带来收益。

# 九、最终项目定位

**Agentic Generative Recommendation: A Memory-Augmented and Judgment-Aware Generative Recommendation System**

中文名称：

**基于用户记忆与结构化判断的智能体生成式推荐系统。**

本项目的核心研究思想是：

将生成式推荐模型的候选生成能力、Memory 的长期用户偏好管理能力、混合召回的商品覆盖能力、Judgment Model 的结构化判断能力，以及 Agent Controller 的自适应决策能力结合起来。

最终实现一个能够理解用户、生成商品候选、验证推荐结果，并动态调整推荐策略的智能体生成式推荐系统。

本次课程设计以完整、可运行、可评测的系统为最终交付目标，为后续各个模块的独立模型训练和优化建立工程基础。
