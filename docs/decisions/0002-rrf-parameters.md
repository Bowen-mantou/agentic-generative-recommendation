# ADR-0002: RRF parameters and tie-breaking

- **状态**：已采纳（k 值待 Phase 7 校准）
- **日期**：2026-11-24
- **上下文**：模块三定义了 RRF 公式 `RRF(d) = Σ 1/(k + rank_m(d))`，但六份文档
  **没有给出 k 的任何数值**（design-contracts T 类缺口），而 AGENTS §2.5 要求
  两级融合且 AGENTS §4 要求参数配置化。

## 决策

1. 两级 RRF 使用相同的平滑常数 **k = 60**（RRF 论文与常见工业基线取值），配置项：
   - `retrieval.e5.rrf_k`（E5 多 Query 内部融合）
   - `retrieval.fusion.rrf_k`（TIGER × E5 跨路径融合）
2. 同分时按 `product_id` 升序排列，保证不同进程/不同 query 顺序下输出完全可复现。
3. 每一级只使用**排名**：E5 内部不累加原始相似度；跨路径不把生成分数与相似度相加。
4. 融合结果保留每个来源的排名与原始分数（`source_ranks` / `raw_scores`），便于
   消融实验与错误分析。

## 理由

- k=60 是 RRF 的常用缺省值，并且对 10–100 量级候选的排名差异不敏感；
- 同 k 让两级融合的分数尺度一致，便于对比消融（E2/E3/E4）；
- 用排名规避异构模型分数不可比的问题（模块三 §5.4 的核心动机）。

## 验证方式

Phase 7 在验证集上扫描 `k ∈ {10, 30, 60, 100}`，报告 Recall@50/100 与 NDCG@10；
在拿到结果前，任何文档不得把 k=60 描述为“已验证最优”。

## 影响

- 单测覆盖了分数计算、权重、重复 ID 拒绝、同分排序（`tests/unit/test_e5_retrieval.py`）。
- Phase 2 跨路径融合直接复用 `fusion/rrf.py`，两级共用同一实现。
