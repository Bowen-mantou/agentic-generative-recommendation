# Phase 4 D1 受控实验与 D11 Gate 结果（A1 / B1 / B2）

- 日期：2026-11-24
- 依据：D1=B（B1→B2 受控实验）、D2（资源上限）、D11（A + 双路增益门槛）
- 结论：**三项配置均未通过 D11 → No-Go；不启动全量训练；Phase 4 不标记完成**
- 产物：`/mnt/agr-data/artifacts/semantic_ids/{rqvae_pilot_a1,rqvae_pilot_a2,samples_a1,samples_b1,samples_b2,generator_pilot_a1,generator_b1,generator_b2}`
- 代码：`scripts/evaluate_tiger_gate.py`（固定评测与 paired bootstrap）

## 1. 固定评测协议

同一实验内固定：商品目录、E5 bundle、时间切分、测试样本、指标与 bootstrap 种子。

| 方法 | 定义 |
|---|---|
| TIGER | 生成器 beam=10 生成 Semantic ID → 解码到商品（桶内按热度/生成分）→ Top-50 |
| popularity | 全库交互热度 Top-50（全用户相同） |
| E5 profile | 用户**目标时间点之前**历史商品 E5 向量均值 → FAISS Top-50 |
| hybrid RRF | TIGER 排名与 E5 profile 排名做 RRF(k=60) → Top-50 |

指标：Recall@10/50、NDCG@10、MRR；对关键差值做 1000 次 paired bootstrap（95% CI）。

**评测修正（如实记录）**：第一次 D11 gate 的 E5-profile 基线错误地使用了用户全部事件（含目标商品），
导致 E5/Hybrid 指标虚高。已修正为只使用 `timestamp < target.timestamp` 的事件，并重跑 A1/B1/B2
全部 gate；本文所有数字均来自修正后的脚本。

## 2. 三组实验配置与数据

| 实验 | RQ-VAE | 序列门槛 | 用户数 | 样本（train/val/test） | 时间边界（train_ts / val_ts） |
|---|---|---|---|---|---|
| A1 | 3×256 | ≥3 事件，history≥2 | 8,201 | 19,222（13,710 / 2,827 / 2,685） | 1,626,820,406 / 1,648,574,591 |
| B1 | 3×256 | ≥2 事件，history≥1 | 43,044 | **62,266**（45,200 / 8,357 / 8,709） | 1,621,974,281 / 1,642,449,475 |

B1「≥2 事件」用户中绝大多数只有 1 条历史，因此样本只比 A1 多约 3.2 倍，而不是 5 倍用户数带来的比例。
B1 的全局时间分位包含 2 事件用户，故时间边界与 A1 不同；B1 报告自身测试集结果（其基线也同集重算）。

## 4. 下游召回结果（修正后的固定协议）

### A1（3×256，≥3）

| 方法 | Recall@10 | Recall@50 | NDCG@10 | MRR |
|---|---|---|---|---|
| TIGER | 0.149% | 0.186% | 0.092% | 0.076% |
| popularity | 0.335% | 0.782% | 0.129% | 0.084% |
| E5 profile | **2.905%** | **4.432%** | 1.405% | 1.012% |
| hybrid RRF | 2.309% | 4.209% | 0.917% | 0.605% |

- D11 条件一（TIGER > popularity）：Recall@10 **-0.186pp**（95% CI [-0.447, +0.037]，p_gt0=0.05）；Recall@50 **-0.596pp**（CI 全负）→ **不通过**。
- D11 条件二（hybrid > E5）：Recall@10 **-0.596pp**（CI 全负）；NDCG@10 **-0.488pp** → **不通过**。

### B1（3×256，≥2，history≥1）

| 方法 | Recall@10 | Recall@50 | NDCG@10 | MRR |
|---|---|---|---|---|
| TIGER | 0.253% | 0.287% | 0.203% | 0.189% |
| popularity | 0.815% | 1.780% | 0.318% | 0.211% |
| E5 profile | **4.352%** | **5.890%** | 2.458% | 1.926% |
| hybrid RRF | 3.617% | 5.649% | 1.638% | 1.137% |

- 条件一：Recall@10 **-0.563pp**（CI 全负）；Recall@50 **-1.493pp**（CI 全负）→ **不通过**。
- 条件二：Recall@10 **-0.735pp**；NDCG@10 **-0.820pp**（CI 全负）→ **不通过**。

### B2（4×1024，≥3）

|---|---|---|---|---|

## 6. D11 判定

| 条件 | 结果 |
|---|---|
| 1. TIGER 超过热度基线（Recall@10 与 Recall@50） | **三项实验均不通过**（CI 均不支持 TIGER 更优） |
| 2. Hybrid 相对 E5-only 有可验证增益 | **三项实验均不通过**（RRF 反而降低 Recall/NDCG） |
| 3. 真实生成链路与可复现性 | 通过：真实 RQ-VAE、真实序列、真实生成、解码到真实商品（合法率 86–95%）、资源与 manifest 记录完整 |

**No-Go 处理（按 D11/Phase4 计划 §2.5 §9）**：

1. 不启动全量训练；A1/B1/B2 产物保留为 pilot 证据；
2. Phase 4 不标记完成；Phase 5/6 使用 E5 候选池继续；
3. Phase 7 如实报告 TIGER-only / popularity / E5 / hybrid 的对照结果；
4. 按 Q12 提交偏差说明，不得把 E5 单路描述为双路召回验收完成。

## 7. 结论与原因

- 提高样本量（B1）使 TIGER Recall@10 从 0.15% 升至 0.25%，但同期 popularity/E5 基线也上升，TIGER
  仍未超过最弱基线；扩大码本（B2）显著改善编码质量（碰撞 3.54%）却使生成更难，Recall 降到 0.07%。
- 生成器在验证集上过拟合（A1/B1 best val 4.9/5.1，B2 5.65→6.77），说明当前数据规模不足以训练
  可泛化的生成式召回；瓶颈是数据，而不是 CPU 算力或编码容量。
- E5 用户画像在相同 next-item 协议下 Recall@10 为 2.9–4.4%，显著强于 TIGER；hybrid RRF 未能带来
  增量（TIGER 候选质量过低，稀释了 E5 排名）。
